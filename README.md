# Buns the Game

A top-down 2D survival game for the browser. Gather wood and stone, craft tools,
smelt ore, farm, keep animals, and stay fed through a day/night cycle in a
procedurally generated, infinitely streaming world.

Built with Next.js 15, React 19 and TypeScript, rendered to a single `<canvas>`.

## Running it

**Prerequisites:** Node.js 20 or newer.

```bash
npm install
npm run dev      # http://localhost:3000
```

```bash
npm run build    # production build (ESLint + TypeScript both enforced)
npm start        # serve the production build
```

## Controls

| Key | Action |
|---|---|
| `W` `A` `S` `D` | Move |
| `Shift` | Sprint (needs hunger above 6) |
| `Space` | Interact / harvest / attack |
| `F` / right-click | Place the held item — a ghost shows where it lands, green if it fits |
| `Space` (holding a bow) | Shoot |
| `E` | Toggle inventory and crafting |
| `1`–`9` | Select hotbar slot |
| `X` | Sit |
| `R` | Respawn at world spawn |
| `N` | New game |
| `Esc` | Pause menu (save, settings, return to main menu) |

On a touch device the game swaps to a virtual stick, USE/PUT/BAG/RUN buttons and
full-screen inventory sheets. Portrait orientation shows a rotate prompt.

## Project structure

```
app/                    Next.js app router entry (layout, page, globals.css)
components/
  Game.tsx              canvas element, React <-> engine bridge, lifecycle only
  MainMenu.tsx          title screen, save browser, options
  ui/                   React DOM overlays: hotbar, inventory, crafting, furnace
src/game/
  core/                 game loop, state shape, tunable config, shared types
  world/                noise, chunk lifecycle, world generation rules
  systems/              pure logic: movement, collision, harvesting, combat,
                        inventory, crafting, smelting, placement, animals,
                        day/night, survival, farming. No React, no DOM, no canvas.
  render/               draw orchestration, terrain, lighting, entities, particles
  assets/               manifest (single source of truth), registry, colliders
  input/                keyboard+mouse, touch, shared input state
  save/                 save schema, serialisation, version migrations
lib/                    sound, debug logging, small shared helpers
scripts/                packing, auditing and maintenance tooling
tools/hearthwood/       the texture generator: palettes, materials, characters
public/                 shipped art: packed atlases only
docs/                   ASSETS.md, IMPORT.md, DESIGN.md, contact sheets, fixtures
```

`src/game/systems/` and `src/game/world/` are deliberately pure TypeScript.
Given `(state, input, dt)` they mutate state and nothing else, which is what
makes them unit-testable without a browser.

## Tests

```bash
npm test          # vitest, single run
npm run test:watch
npm run typecheck
npm run lint
```

```bash
npm run test:smoke    # headless browser: boots, renders, survives a session
npm run test:mobile   # touch controls and portrait handling
npm run test:loop     # long-run stability, memory, chunk streaming
npm run test:world    # world generation invariants
```

185 unit tests cover inventory, crafting, smelting, noise determinism, hit
testing, held-item grips, the asset manifest and whether a new game can be
started at all — the systems that break silently when refactored.

`TEST_CHECKLIST.md` is the 25-step manual regression pass. Run it after any
change that touches gameplay.

One thing worth knowing: the unit tests all assert on game *state*, so they
happily passed while 35 of 52 entity types were never actually drawn. A test
that never looks at the screen cannot tell you the screen is empty. `test:smoke`
takes screenshots for this reason.

## Assets

All shipped art lives in a handful of packed atlases under `public/sprites/`, and
every frame is declared in `src/game/assets/manifest.ts` — the single source of
truth for frame rectangles, anchors, world sizes and colliders.

Every texture is generated by **Hearthwood**, a deterministic Python pipeline in
`tools/hearthwood/`. No model calls, no API key, no network — 203 frames in
about 17 seconds, byte-identical every time. Materials are painted as index maps
into 7–9 step OKLab colour ramps and graded once at the end, which is why a
pine tree and an iron ingot look like they were lit by the same afternoon.

```bash
npm run assets:all        # sizes -> art -> pack -> contact sheet -> audit
npm run audit:assets      # referenced-but-missing / present-but-unused, payload size
```

`npm run audit:assets` must report **0 missing, 0 unused**; it exits non-zero
otherwise so it can gate CI.

- **[docs/ASSETS.md](docs/ASSETS.md)** — the palettes, the pipeline, the checks,
  and how to add one asset end to end.
- **[docs/IMPORT.md](docs/IMPORT.md)** — importing into an engine. Point/nearest
  filtering, no compression, mipmaps off; this art does not survive bilinear.
- **`docs/contact/hearthwood.png`** — every asset at 8×, every tile at 3×3, and
  the ground materials on isometric cubes.

Art is **0.27 MB** for 203 frames, against a 3.5 MB budget.
